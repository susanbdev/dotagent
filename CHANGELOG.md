# Changelog

All notable changes to `dotagent` are documented in this file.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [2.2.0] - 2026-11-24

### Added
- **Anti-Shim, Fail-Closed, & Polyglot Golden-Vector Audit Laws (`repo_audit.rs`, `smoke_gate.rs`, `qa_suspects.rs`, `diagnostics.rs`)**: Added `NO_UNLINKED_RUNTIME_SHIM` (requiring Cargo + Wrangler workspaces to link compiled `wasm32-unknown-unknown` `.wasm` modules with `<= 150`-line host FFI glue, capping non-test `.mjs`/`.js` files at `<= 150` SLOC, forbidding imperative `scripts/deploy.py` REST bypasses where `.tf` modules exist, and blocking `primitives/dotagent` `dash` stubs and RFC 8032 test keys), `NO_FAIL_OPEN_FALLBACK` (blocking `catch` blocks returning `clean/restored=true`, synthetic container fallback adapters, and Worker `sqlite3` CLI shells), and `POLYGLOT_GOLDEN_VECTORS` (requiring shared `vectors/*.json` round-trip tests across Rust, TypeScript, Python, and C11).
- **Canonical Root `./scripts/check` Gate**: Added executable `./scripts/check` matching sibling `susanbdev` repositories across ASCII/Unicode hygiene, `cargo fmt`, `clippy`, workspace tests, packaging unittests, release compiler/audit verification, and `StopReceipt` attestation.

### Security
- **Warm `hook-daemon` Env Hygiene & Per-Request IPC Session Scoping (`coordinator.rs`, `path_policy.rs`, `lib.rs`)**: Added `AGENT_GUARD_DIRECT_EXPLORE` to `spawn_hook_daemon_process` env scrubbing, prevented `hook.sock` requests from falling back to ambient daemon `AGENT_GUARD_DIRECT_EXPLORE`, threaded `session_id` explicitly via `ScopedRequestSession` and `resolve_max_walk_depth` so `SwarmRole::Investigator` preserves `INVESTIGATOR_MAX_WALK_DEPTH` (`6`) over warm `hook.sock`, and replaced the lossy static `KNOWN_GUARD_CODES` whitelist with catalog lookup plus bounded validated reason-code interning.
- **Full Ancestor `O_NOFOLLOW` Outbox Walk (`feedback_loop.rs`)**: Updated `write_atomic_outbox_file` to verify `symlink_metadata` across every intermediate ancestor directory component rather than only `out_path` and its immediate parent.

### Security
- **Trusted-Base Ratchet Verifier, `integration_id` Pinning, & Decoy-PR Defense**: CI and `copilot-gate.yml` compile `verify-ring0-ratchet` from the default-branch base (never PR sources), with no build cache and no `GH_TOKEN` in any step that compiles or executes repository code. `copilot-gate.yml` refuses to post a commit status when `pull_request.base.ref != repository.default_branch`, required status checks in `dotagent-zero-trust-main` are pinned to `integration_id: 15368` (GitHub Actions), and the loop GitHub App token is downscoped to `contents: write`, `pull_requests: write`, and `issues: write` only (zero `workflows`, `statuses`, or `administration` permissions).
- **Sandboxed Loop Stages, Sandboxed Verification, & Single-Use Token File**: Every `run-loop` stage (including the Stage 3 implementer) and every worktree Cargo verification step (`dotagent-compiler verify`, `cargo fmt`, `cargo clippy`, `cargo test`, `dotagent-harness --suite all`) runs inside `agent-guard exec-sandbox`; read-only stages add `--read-only --deny-net` and verification steps run with `--deny-net`, `CARGO_NET_OFFLINE=true`, and zero LLM keys. Hosted-LLM keys (recommended to be dedicated, spend-capped keys) are forwarded only to networked stages (`!read_only || DOTAGENT_LOOP_STAGE_ALLOW_NET=1`), and the GitHub token is passed via an ephemeral `0600` `DOTAGENT_LOOP_GITHUB_TOKEN_FILE` that is zeroed and unlinked on startup and supplied to `git push` solely as a scoped `http.https://github.com/.extraheader` against an explicit HTTPS repository URL.
- **Fleet Image Provenance**: `dotagent fleet build-image` requires provenance (SSH-signed tag verified against `config/allowed_human_signers`, or on-`main` with green main-push check-runs); `--allow-unverified-local` opts into developer-only images.

## [1.0.0] - 2026-11-18

### Security
- **Fail-Closed CLI, JSON, & Session Ledger**: Unrecognized CLI subcommands across `agent-guard`, `dotagent`, `swarm-tool`, `dotagent-compiler`, and `dotagent-harness` exit `2` (`UNKNOWN_SUBCOMMAND`). Duplicate JSON object keys (`RFC 7493` I-JSON smuggling) and corrupt/truncated `SessionLedger` files (`CORRUPT_SESSION_STATE`) fail closed under exclusive `flock` locking while preserving sticky `halted`/`tainted` flags across concurrent writers.
- **Audited Cryptography & Privilege-Separated Coordinator**: Replaced custom SHA-256 code with `sha2::Sha256`, `hmac::Hmac<Sha256>`, `subtle::ConstantTimeEq`, and volatile `ZeroizingKey`. Hardened `coord.sock` (`0700` parent pre-bind, 16-worker pool, boolean-only MAC verification RPCs, `PLAN_LOCK` and `master` capability minting blocked over IPC, and strict capability/plan path-scope validation).
- **OS Sandbox Hardening (`exec-sandbox`)**: Added Linux `6.7+` Landlock `V4` `AccessNet::BindTcp | ConnectTcp` enforcement under `--deny-net` (failing closed under `--require-kernel` when `AccessNet` is unavailable), bounded background pipe draining to prevent `SIGPIPE` truncation, `process_group(0)` timeout termination, `--norc --noprofile` shell hygiene, `.git` index lockfile support, and escaped macOS `sandbox-exec` SBPL profiles.
- **Shell Lexer Forward-Progress Guarantee**: Fixed unmatched `)` and empty redirection edge cases in `cmd_policy` (`UNBALANCED_SUBSHELL` / `MALFORMED_REDIRECTION`) uncovered by property-based fuzzing.

### Added
- **Unified `dotagent` Multicall Operator CLI**: Added `dotagent doctor [--json]`, `dotagent explain <CODE|--list> [--json]` (33-code remediation catalog), interactive human-TTY `dotagent session-reset`, non-destructive `dotagent activate` / `dotagent deactivate` (with `.dotagent.bak` backups, JSON user-preference preservation, `~/.bashrc` + `~/.zshenv` `PATH` setup, and pinned absolute GUI hook paths), and `swarm` / `compile` / `harness` subcommand delegation.
- **Swarm v2 Architecture (`swarm-tool`)**: Six least-privilege roles (`master`, `investigator`, `qa-engineer`, `grunt`, `adversarial-reviewer`, `forensic-coroner`), full-record HMAC breadcrumbs with `CRC32` crash spool recovery, upfront `1 / 0..2 / 0..N` QA fault triangulation, and abbreviation-aware `2+2` Work Ledger stop gates.
